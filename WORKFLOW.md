## 🚀 Быстрый старт

### 1. Локальный сервер (рекомендуется)
```bash
# Python 3
python -m http.server 8000

# Node.js
npx serve .

# VS Code: расширение "Live Server" → Go Live
```
Открой `http://localhost:8000`

### 2. Локальный файл (без сервера)
Просто открой `index.html` двойным кликом. Используй кнопку **"📂 Выбрать roles.json"** для загрузки ролей.

## 🔄 Полный цикл аудита (пошагово)

### Шаг 1: Загрузка ролей
1. Перейди в **⚙️ Настройки**
2. Нажми **🔄 Загрузить роли** (если на сервере) или **📂 Выбрать roles.json** (если файл)
3. Убедись, что статус показывает "X ролей загружено"

### Шаг 2: Загрузка проекта (НОВОЕ)
1. Перейди в **📦 Проект**
2. Перетащи ZIP-архив проекта в зону или нажми для выбора
3. Система покажет структуру файлов и их языки
4. Нажми **🔍 Анализировать зависимости**
5. Получи отчёт: циклы, dead code, impact map, orphans

### Шаг 3: Ввод задачи
1. Перейди в **📝 Ввод**
2. Вставь описание задачи в "Задача / Контекст"
3. Вставь полный ответ Мастера с `[ORCHESTRATOR_PLAN]`
4. Нажми **🚀 Распарсить план**

### Шаг 4: Распределение ролей
1. Перейди в **🎯 Роли**
2. Для каждой роли:
   - Нажми **📋 Копировать** промпт
   - Открой Kimi (кнопка **↗️ Kimi**)
   - Вставь промпт, получи ответ
   - Вставь ответ в поле **✍️ Ответ роли**
3. Статус изменится на ✅

### Шаг 5: Сбор результатов
1. Перейди в **📥 Сбор**
2. Проверь, что все ответы на месте
3. Нажми **🧩 Сгенерировать combined.md**

### Шаг 6: Финальный отчёт
1. Перейди в **🏁 Финал**
2. Система автоматически:
   - Соберёт все ответы
   - Найдёт конфликты между ролями
   - Предупредит, если есть противоречия
3. Скопируй отчёт или отправь в Kimi

## 📊 Тестирование больших проектов (много файлов)

### Стратегия 1: ZIP-архив (рекомендуется)
```bash
# Упакуй проект
zip -r my-project.zip my-project/ -x "node_modules/*" ".git/*" "*.log"

# Или через терминал
# cd my-project
# zip -r ../project.zip . -x "node_modules/*" -x ".git/*"
```
Перетащи `my-project.zip` в Voyage. Система:
- Распакует архив в памяти (без сервера)
- Определит язык каждого файла
- Построит граф зависимостей
- Найдёт циклы любой длины (DFS)
- Определит мёртвый код
- Построит карту влияния (если изменить X → сломается Y, Z)

### Стратегия 2: Постепенная загрузка (для очень больших проектов)
Если ZIP > 50 МБ или файлов > 1000:
1. Разбей проект на части по модулям
2. Загружай по одному модулю
3. Анализируй каждый модуль отдельно
4. Собери общий отчёт вручную

### Стратегия 3: Выборочный анализ
Для проектов с 1000+ файлов:
1. Загрузи только entry points (index.js, main.py, app.go)
2. Загрузи критические модули (auth, payment, core)
3. Пропусти vendor/, node_modules/, .git/

## 🎯 Как использовать анализ зависимостей

### После загрузки ZIP:
1. **Граф зависимостей** показывает связи между файлами
2. **Циклы** (🔴) — критические проблемы, требуют рефакторинга
3. **Impact Map** — если изменишь файл X, узнай что сломается
4. **Dead Code** — экспортированные символы, которые никто не использует
5. **Orphans** — файлы без связей (возможно, лишние)

### Пример использования:
```
Вывод: "Если изменить auth.js, сломаются: api.js, dashboard.jsx, settings.ts"
→ Значит перед рефакторингом auth нужно:
  1. Написать тесты для api, dashboard, settings
  2. Проверить контракты интеграции
  3. Использовать feature flag
```

## 🛡️ Безопасность

- **CSP**: `script-src 'self'` (без 'unsafe-inline')
- **XSS**: Все пользовательские данные экранируются через `escapeHtml()`
- **DOM**: Нет `innerHTML` для пользовательского ввода — только `textContent` и `createElement`
- **Валидация**: Импортированный JSON проверяется на prototype pollution
- **Размер**: localStorage ограничен 4 МБ, большие сессии экспортируются в файл

## 💡 Советы

1. **Для GitHub Pages**: Загрузи роли через File API, сервер не нужен
2. **Для мобильных**: Используй GitHub Codespaces + Live Server
3. **Сессии**: Экспортируй перед закрытием браузера
4. **Роли в Kimi**: Копируй промпт, вставляй в новый чат, получай ответ, возвращайся в Voyage
5. **Большие ответы**: Если ответ роли > 4000 символов, разбей на части
